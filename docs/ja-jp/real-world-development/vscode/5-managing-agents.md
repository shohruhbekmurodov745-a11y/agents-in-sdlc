GitHub Copilot を agent mode で使うと、コードベースを調べ、変更を提案してファイルを編集し、コマンドを実行します。VS Code の Copilot Chat では、自分のマシンでリアルタイムに実行される各ツールの呼び出しやファイルの編集を確認できます。差分をインラインでレビューし、個々の変更を承認または取り消し、エディターを離れずに追加のプロンプトで会話を導いて作業を改善したり広げたりできます。

この演習では、次の操作を行います。

- アクセシビリティエージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集を確認して承認します。
- 実行中のセッションでエージェントに指示し、ハイコントラストに加えてライトモードの切り替え機能を追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ用カスタムエージェントが、ハイコントラストモードを実装しています。作業中にデザインチームから追加の依頼がありました。既定のテーマを暗すぎると感じるユーザー向けに、ライトモードの切り替え機能も追加します。新しい会話を始める代わりに、既存のセッションを導いて作業を広げます。

## Copilot の進行状況を監視する

Copilot Chat ビューには、エージェントが調べたファイル、実行したコマンド、提案した編集など、作業の各手順が表示されます。ファイルの編集は差分と **Keep** / **Undo** の操作とともにチャットに表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントが作業している間、チャットをスクロールしてツールの操作を確認します。ファイルの読み取りや編集、実行しようとするターミナルコマンドが表示されます。
3. エージェントがファイルの編集を提案すると、差分がインラインで表示されます。
    - 変更を適用するには **Keep** を選択します。
    - 変更を取り消して、エージェントにもう一度試させるには **Undo** を選択します。
4. チャット上部の **Files changed** を開くと、セッション中にエージェントが変更したファイルを一覧できます。

> [!NOTE]
> ターミナルコマンドの実行などに権限が必要な場合、エージェントは **Allow** を求めて一時停止します。許可するコマンドを確認してから承認してください。

5. エージェントがハイコントラストモードを実装し終えるまで待ちます。最後に変更の概要が表示されます。

## エージェントにライトモードを追加させる

ハイコントラストモードができたら、同じ会話でライトモードの切り替え機能も追加します。同じチャットセッションを続けるため、エージェントは以前の作業で使ったコンポーネントやスタイル設定、ローカルストレージのパターンを把握しています。

1. Copilot Chat の入力欄に次の追加プロンプトを送信します。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントは既存の変更を調べ、ライトモードの追加を提案します。
3. 変更が提案されるたびに、ハイコントラストの場合と同様にレビューします。各差分で **Keep** または **Undo** を選択します。
4. たとえば、トグル UI のリファクタリングなど、意図と異なる方向に進んだ場合は、チャット入力欄の横にある **Stop** ボタンで停止し、補足のメッセージを送信します。

> [!TIP]
> 実行中のセッションを導く方が、最初からやり直すより早く済みます。追加プロンプトで調整（「CSS を簡潔にし、セレクターの重複ではなく CSS 変数を使う」）、軌道修正（「3 つ目のトグルは追加せず、既存の設定パネルにライトモードを組み込む」）、範囲の拡張（「両方のトグルにキーボードショートカットも追加する」）を依頼できます。

## 作業内容をレビューする

コミットする前に、エージェントが変更したすべてのファイルを確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストなどが更新されているはずです。
3. 変更されたファイルをいくつか開き、差分を確認します。カスタムエージェントのアクセシビリティパターン（ARIA 属性、キーボード操作、セマンティック HTML、ローカルストレージによる設定の保存）が反映されていることを確認します。
4. 問題がなければ、Source Control パネルで変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat の agent mode で、進行中のセッションを監視して方向づけました。ファイル編集ごとに確認し、変更を承認または取り消し、コンテキストを保ったまま追加プロンプトで作業を広げました。

このレッスンでは、次の操作を行いました。

- エージェントの作業をリアルタイムで監視しました。
- 個々のファイル編集を承認または取り消しました。
- 追加プロンプトで実行中のセッションを導きました。

[次のレッスン][next-lesson]では、アクセシビリティの変更をプルリクエストとして公開し、このラボ全体でカスタムエージェントが作成した変更をレビューします。
